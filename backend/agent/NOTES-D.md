## The verified limits (provenance strings live in `limits.PROVENANCE`)

- mould_temp_C: normal 180–210 °C, steam-direct specifically 190–210 °C.
  Source: "presse de cuisson pneu, vapeur directe".
- pressure_bar: TWO source formulations kept verbatim — ">20 bar" normal AND
  "1.6–1.9 MPa" steam-direct = 16–19 bar. Never merged; the 19–20 bar gap is
  "indeterminate — two source formulations" → tier-1 WATCH, never an alarm.
- cycle_min: 10–15 min normal, up to 30 min depending on tyre size/type;
  >30 = overrun (hard flag), <10 = short/undercure risk (hard flag),
  15–30 = extended (soft WATCH).
- vibration_rms_mm_s: ISO zones A ≤1.12 / B ≤2.8 / C ≤7.1 / D >7.1.
  Source: ISO 10816-3 / ISO 20816-3, Group 2 (driven machines 15–300 kW,
  rigid foundation) — GENERAL industrial reference, NOT measured on this
  specific press; treat as a starting reference (caveat kept in provenance).
  Tier-1 mapping: A/B pass, C → "ISO zone C — surveillance", D → "ISO zone
  D — danger".
- CL-03 thermal_margin_K floor 8 (AI4I HDF) and MX-02 torque/wear (AI4I
  PWF/OSF) moved into limits.py so specs have ONE home.

## TROUBLESHOOTING LOG (deviation → root cause → fix → re-run)

Baseline harness run (new scenarios vs PRE-fix modules): 8/11 PASS,
3 DEVIATION rows. Every deviation was classified before fixing:

1. **S1 DEVIATION — nominal steam cure false-alarms the spec.**
   `run_diagnostic` reported `mould_temp_C at/beyond TRIP limit (195.0)` and
   `vibration_rms_mm_s under operating floor (1.5)` for a HEALTHY verified
   cure. Root cause = **component bug (the exact class Eric predicted)**: old
   invented RC-07 spec in `operator_tools.MACHINE_SPECS` — mould_temp
   operating [150,185] + trip 195 (a healthy 196 °C steam cure trips it),
   vibration operating floor 1.5 (healthy zone-A 0.9 mm/s is "under floor"),
   pressure [14,22] (wrong on both ends vs 16–19 / >20). Fix: D4-tools-v1,
   specs read from `limits.py`. Re-run: S1 PASS with 0 spec hits.
   *Secondary find in the same row — harness bug of mine*: the S1 diag check
   originally ran after S6 was already ingested, so `run_diagnostic` (which
   reads the LATEST reading) was judging S6's data. Root cause = harness
   expectation wiring wrong, not a component bug. Fix: scenarios are now
   processed strictly in order, each check before the next ingest.

2. **S4 DEVIATION — tier-1 reasons named no physical limit.**
   Reason was only "health 12% under hard floor 45%; residual 0.90 …" —
   nothing about 214 °C, zone D or the pressure band. Root cause =
   **component gap**: triage tier-1 had NO curing signal checks at all.
   Fix: D4-triage-v1 `_curing_signal_flags()` — reasons now read e.g.
   "mould_temp 214.0°C above 210 normal ceiling; pressure 15.20 bar below
   the 16-19 bar steam-direct band (under both source formulations);
   vibration_rms 8.20 mm/s — ISO zone D — danger (over 7.1 mm/s)".
   Re-run: PASS (risk CRITICAL, jury passed, digits cited).

3. **S6 DEVIATION — 31-min cycle overrun triaged CLEAR ("within envelope").**
   Root cause = **component gap (false-negative class)**: no cycle check
   existed anywhere; health 0.8 sailed through the generic envelope. Fix:
   `cycle_status()` in limits.py + tier-1 hard flag for overrun/short and
   soft WATCH for extended (15–30). Re-run: PASS — HIGH + advisory,
   reason "cycle 31.0 min beyond the 30 min extended ceiling (10-15 normal)".
   Note: the S6 note carries "anomal(y)" per the documented mock-note
   discipline (genuinely anomalous notes carry a trigger word — that is the
   offline MockClient tier-2 contract, NOT an expectation fudge).

4. **Regression break — test_operator_agent_mock check 5.**
   `assert spec["signals"]["vibration_rms_mm_s"]["trip"] == 7.0` failed after
   the fix. Root cause = **test expectation encoded the old invented limit**
   (7.0); the verified ISO zone-D floor is 7.1. Fix: minimal heal-edit,
   7.0 → 7.1 + `D4-regression-v1` comment. Re-run: 12/12 green.
   test_service_mock needed NO change: the note arc (CLEAR ≤5 / HIGH 6–9 /
   CRITICAL ≥10), determinism and health-degradation assertions were
   deliberately preserved by the rescale. test_pipeline_mock unchanged/green
   (its RC-07 "CRITICAL" fixture uses lowercase `mould_temp_c` = 178.4,
   which the new case-insensitive check flags as below the 180 floor — one
   MORE correct reason on an already-escalating reading).

  band will false-alarm nominal steam cures — read `limits.py` instead.

  (indeterminate between the two source formulations) — don't "fix" that.
- Tier-1 can now return WATCH directly (soft flags only: pressure gap,
  extended cycle, 180–190 °C sub-steam band) without waking tier 2.

  operator agent can (and should) cite them verbatim.

  return WATCH where the mock returns CLEAR (S8 zone-C ticks) — the harness
  accepts both (≤WATCH assertions).
